Jarvis Session Management Blueprint

Architecture, Contract Hierarchy, and Execution Phases (2026-11-08)
T3 First-Class 3-Phase Plan

1. The 3 Architectural Tiers

Tier 1: T3 Code First-Class

Independent, rich orchestration. Projects, git worktrees, threads, and Effect RPC WebSocket (protocol 2).

orchestrator.t3: T3Adapter
├── shell_snapshot()
├── open_project(folder, task)
└── attach(thread_id, root)
✦ Reached explicitly via orchestrator.t3
✦ No duck-typing (hasattr/isinstance deleted)
Tier 2: Coding Clients One Contract

Claude Code, OpenCode, and Pi. Share one session lifecycle contract over distinct transports.

CodingSessionAdapter
├── list_sessions(cwd, limit)
├── pick_session(session)
└── new_session(cwd)
✦ Claude: Agent SDK resume / fork
✦ OpenCode: HTTP /api/session
✦ Pi: Unix domain sockets (~/.config/jarvis/pi)
Tier 3: Hermes Agent Base Only

Non-coding generalist (notes, calendar, research). No coding sessions managed by Jarvis.

BaseAgentAdapter
├── send_task(task)
├── answer(answer)
├── interrupt()
└── busy: bool
✦ Hermes manages its own gateway runs
✦ Untouched by session refactoring

4. Phased Implementation Roadmap

PHASE 1

The Contract, Keyboard Picker, & Clean T3 Reference

• Create src/jarvis/sessions.py: AgentSession, CodingSessionAdapter, and match_sessions().
• Implement adapter methods in claude_adapter.py, opencode_adapter.py, and pi_adapter.py.
• Add explicit orchestrator.t3 property; delete duck-typing checks in agent_tools.py, prompts.py, and main.py.
• Generalize jarvis connect [client] in cli.py and main.py.
• Safety gate: No prompt or tool schema modifications. Unit tests and mypy must pass.

PHASE 2

Voice Session Selection via Pipecat Tool

• Add optional session property ("new" or search words) to send_agent_task (keeps 3 tools total, avoids tool bloat).
• Populate top 5 recent sessions per coding agent in system prompt (like project_list) for zero-latency memory recall.
• Safety gate: Run scripts/bench_routing.py before and after; accuracy must stay ≥ 95%.

PHASE 3

Triggered RAG Over Deep Transcripts

• Triggered only if user feedback confirms titles/first prompts are insufficient for retrieval.
• Index message transcripts via claude_agent_sdk.get_session_messages() and OpenCode message endpoint into a local jarvis_sessions Qdrant collection.
• Embed using local Ollama bge-m3 (zero API cost, ~20 ms latency, same stack as memory.py).

5. Key Architecture Decisions & Safeguards

No Tool Bloat

Rather than a 4th tool (manage_agent_session) which dilutes LLM attention, session intent is unified into send_agent_task(..., session="...").

Busy State Protection

Restarting Claude's SDK client mid-turn drops in-flight work. pick_session and new_session reject while busy is True.

Crash Context Preservation

If Claude Code CLI restarts unexpectedly, Jarvis now re-attaches to the exact same _session_id and informs the user instead of wiping state silently.
